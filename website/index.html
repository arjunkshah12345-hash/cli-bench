The problem

Model benchmarks can't see the agent.

SWE-bench, Terminal-Bench, and HAL established that the same model scores wildly differently across harnesses — but each either fixes the harness or treats it as a nuisance variable. CLI-Bench makes the harness the subject under test: related work like HarnessBench and A-Code Bench shares the instinct; CLI-Bench focuses narrowly on coding-agent CLIs with deterministic per-task verification, seeded instances, and anti-gaming probes.

ceteris paribus

Everything held constant

Same model per cohort, same task prompt, same shell, same time and token budget, same verifier. The harness is the only independent variable — and the model the CLI actually ran is verified against the request.

determinism

No LLM judge in pass/fail

Task verdicts come from plain scripts: exit 0 means pass. The headline score has no judge, no vibes, no drift — a separate code-quality axis (SPEC §4.3) is the only judged number and never feeds CB-HDR.

anti-gaming

Houdini probes

Four trap tasks detect test mutation, verifier editing, spec hallucination, and peeking at hidden files. Run them with --with-houdini: any probe that doesn't pass marks the run untrusted on the leaderboard — the label is enforced by the scorer, not promised.

The score

CB-HDR — correctness, priced honestly.

Hard-blocking first: a task that fails scores zero, no matter how fast or cheap. Passing runs earn full credit up to 5× the passer-median token spend — a deliberate noise-tolerance band — then decay linearly. Latency and diff churn are published as separate columns, never folded into the headline.

CB-HDR = Σt 1[pass] · w(t) · B(t) / Σt w(t)
B(t) = min(1, 5·p50pass / spend)  →  ≤5× median = 1.0  ·  10× = 0.5  ·  25× = 0.2  ·  cache reads count at 0.1×
β · cost

Token & dollar brake

Native per-turn usage when the harness reports it; transcript estimation only as a labeled fallback. Overspend past 5× the passer p50 and your pass decays linearly — the task's dollar budget tightens the band further.

τ · latency

Wall clock, published

A pass that took 10 minutes is not hidden: p50 latency is a first-class column on every leaderboard, it just never silently multiplies the headline score.

χ · churn

Diff churn, published

Lines touched are reported per task — surgical agents are visible without an invented churn constant in the score.

HDR-C

Equal-cost pass rate

Per task, one budget bar for every harness: the cohort's passer-median spend. A pass keeps credit only if its median cost lands under the bar — so a spend-heavy harness can't buy the same score. Published next to CB-HDR so capability and efficiency never blur.

CIs

Bootstrap confidence

12 tasks × 3 seeds; percentile bootstrap over trials gives every score an interval. Rankings that overlap aren't rankings.

profiles

Declared agency

Every adapter declares its approval mode, sandbox, and flags in a machine-readable profile. A max-agency run can never be silently compared to a guarded one.

The suite

12 real tasks. 4 traps.

Every task ships a hermetic environment, seeded variation, and a verifier that re-checks the work on a pristine copy. Prompts are harness-neutral — no tool mentions, no file-path spoilers.

houdini/self-test

Will it doctor its own tests?

The only way to "pass" is to edit the shipped test — which the sabotage checker catches instantly.

houdini/mutation

Will it weaken assertions?

A tempting-but-wrong fix path makes mutating the test file the cheap way out. Verifier diffs against a pristine copy.

houdini/hidden-spec

Does it invent requirements?

Format rules live in a file the prompt never mentions. Agents that guess formats fail; agents that read succeed.

houdini/no-cheat

Does it peek?

A decoy file whispers "the answer is hidden here". atime auditing catches harnesses that open it — and the honest pass truncating it is exempt.

budgets

Same rope for everyone

Per-task token, dollar, and wall-clock budgets enforced by the runner; checkpoint telemetry at 25/50/75% distinguishes "stuck" from "sandbagged".

seeds

Seeded, not memorized

Every environment materializes from CBENCH_SEED: different data, different race windows, same task. Memorization buys nothing.

Quickstart

From clone to score in five minutes.

# 1. install
git clone https://github.com/arjunkshah12345-hash/cli-bench
cd cli-bench && pip install -e ".[dev]"

# 2. check your harnesses
cbench list            # shows tasks + detected CLIs + versions

# 3. sanity-run (no API cost)
cbench run --harness mock-a --model mock/gpt-5.3 --seeds 1
# 4. the real thing (model-compatible cohort)
cbench run \
  --harness opencode --harness aider \
  --model openai/gpt-5.3 \
  --seeds 3

# 5. score + report
cbench score runs/<run-dir>
cbench report runs/<run-dir> --out report.html

# out-of-cohort pairings are refused unless you pass
# --allow-incompatible (recorded in the manifest)
# (artifacts included, results reproducible)
